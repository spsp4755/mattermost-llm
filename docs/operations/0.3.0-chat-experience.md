# v0.3.0 운영 및 검증 기록

## 관리자 설정

System Console → Plugins → Mattermost LLM의 봇별 설정에서 지정합니다.

- **Reasoning 표시:** 기본 숨김. 필요한 봇만 접어서 표시합니다. 숨김이면 새 응답의 reasoning을 스트리밍·게시물·디버그 출력에서 제외합니다. 표시하면 사용자에게 전달되므로 접힌 UI는 접근 제어가 아닙니다.
- **Thinking 생성:** 기본은 서버 기본값 유지입니다. 켜기/끄기를 지정할 때는 실제 추론 서버가 받는 파라미터 형식을 함께 선택합니다. 모델 이름을 바꿔도 표시 정책은 유지됩니다.
- **대화 자동 열기:** 기본 활성화. 질문자가 현재 보고 있는 채널에서 요청한 경우에만 오른쪽 스레드를 엽니다. 다른 사용자의 질문이나 이미 이동한 채널의 응답은 화면을 전환하지 않습니다.
- **자동 그림:** 일반 chat/multimodal의 markdown 또는 rich 출력에서 모델이 설명에 도움이 될 때 Mermaid를 선택하도록 안내합니다. 단순 답변에는 그림을 강제하지 않습니다. 충실한 OCR의 일반 markdown 및 text/json 출력은 제외합니다.

| 추론 API의 형식 | 끄기 요청 예 | 사용 시 확인할 사항 |
| --- | --- | --- |
| `chat_template_kwargs.enable_thinking` | `{"chat_template_kwargs":{"enable_thinking":false}}` | vLLM의 모델별 chat template 지원 여부 |
| `chat_template_kwargs.thinking` | `{"chat_template_kwargs":{"thinking":false}}` | 해당 template의 키 이름 확인 |
| `thinking.type` | `{"thinking":{"type":"disabled"}}` | DeepSeek/GLM/Kimi 등의 해당 API·모델 버전 지원 여부 |
| `enable_thinking` | `{"enable_thinking":false}` | 이 최상위 키를 받는 호환 서버만 사용 |

명시한 생성 설정은 추가 요청 JSON의 동일한 키보다 우선하며 다른 키는 보존합니다. 2차 후처리 서버는 다른 모델/API일 수 있으므로 1차 서버의 생성 파라미터를 전달하지 않습니다. 2차 결과에도 표시 정책은 적용됩니다. 추가적인 제공업체 옵션은 기존 추가 요청 JSON으로 지정할 수 있습니다.

생성 끄기를 지원하지 않는 모델은 서버 기본값을 유지하고 표시만 숨기세요. 예를 들어 MiniMax M2 계열은 thinking을 끌 수 없으며, MiniMax의 일부 신형 API는 켜기에 `enabled` 대신 `adaptive`를 사용합니다. 이 경우 기본값 유지와 제공업체별 추가 JSON을 사용합니다. 모델 이름만 보고 파라미터를 추측하지 않습니다.

명시적 reasoning 필드(`reasoning_content`, `reasoning`, `thinking`), typed block, 응답 앞부분의 think/thinking/reasoning/analysis 태그와 명시적 reasoning/answer 구분을 처리합니다. 구분 없이 일반 문장으로 섞인 사고 과정은 확실히 분리할 수 없으므로 서버의 reasoning parser를 설정해야 합니다. 과거 게시물의 저장된 내용은 소급 삭제하지 않습니다.

## 그림 및 팝업

한글의 짧은 노드 라벨, 위에서 아래로 읽는 구조, 제한된 노드 수, 접근성 제목·설명, 텍스트 요약을 생성 지침에 포함했습니다. 데이터가 없는 수치 차트는 만들지 않도록 지시합니다. Mermaid는 오프라인 번들로 렌더링하며 테마, 코드 보기, 복사, SVG 저장을 제공합니다. 팝업은 document.body에 표시해 채팅 스크롤 위치의 영향을 피하고, 전체 그림 맞춤·50–300% 확대·Escape·포커스 복귀를 지원합니다.

이 기능은 다이어그램 렌더링입니다. 사진 생성이나 임의의 HTML 앱 생성은 포함하지 않습니다. 그림을 선택하는 판단과 내용의 정확도는 연결한 모델에 달려 있으며 ChatGPT/Claude와 동일한 생성 품질을 보장하지 않습니다. 모바일처럼 웹 플러그인을 실행하지 않는 클라이언트에는 Markdown/Mermaid 원문이 보입니다.

## 조사와 적용 근거

- [Mattermost 10.11.10 RHS 동작](https://github.com/mattermost/mattermost/blob/v10.11.10/webapp/channels/src/actions/views/rhs.ts): 해당 버전의 SELECT_POST payload에 맞춰 구현했습니다.
- [Mattermost Agents](https://github.com/mattermost/mattermost-plugin-agents), [호환 hooks](https://github.com/mattermost/mattermost-plugin-agents/blob/master/webapp/src/hooks.tsx): 기존 버전용 스레드 열기 방식을 비교했습니다. Apache-2.0 라이선스를 확인했으며 소스 블록을 가져오지 않고 기존 플러그인 구조 안에 구현했습니다.
- [vLLM reasoning 출력](https://docs.vllm.ai/en/stable/features/reasoning_outputs/): 모델/템플릿별 차이를 확인하고 표시 정책과 생성 제어를 분리했습니다.
- [DeepSeek thinking](https://api-docs.deepseek.com/guides/thinking_mode/), [Kimi K2.5](https://github.com/MoonshotAI/Kimi-K2.5), [GLM thinking](https://docs.z.ai/guides/capabilities/thinking-mode): 명시적 API 파라미터 선택의 근거입니다.
- [MiniMax OpenAI 호환 API](https://platform.minimax.io/docs/api-reference/text-openai-api): 태그/별도 reasoning 필드와 모델별 생성 제한을 확인했습니다.

REA 6.7.0으로 실제 v0.2.0 배포 JavaScript에서 팝업 함수를 추출해 정적 분석했습니다. 전체 번들은 시간 제한으로 종료되어, 원본 문자열 offset 6975614..6978896의 정확한 함수 범위로 좁혔습니다. 원본 SHA-256: `f6a935fb7bcbe1f4dc05e1294d9c18e9a31f3ca499403308321379c54bdeb3db`. 분석한 3,420바이트/794 AST 노드에 파싱 오류는 없었습니다. Evidence ID: `ev_5b8bf19630eda73027fa1621e8cec4c169e8794d1510ce2cfc78eb64fb988c8f`. 이 정적 증거만으로 CSS 원인을 단정하지 않았으며, 소스·포털 회귀 테스트·실제 브라우저로 확인했습니다. 이 함수 밖의 호출·동적 동작은 REA 분석 범위에 포함되지 않습니다.

## 검증과 배포

- Go 전체 테스트, TypeScript 타입 검사, 프런트엔드 37개 테스트, 프로덕션 webpack 빌드.
- linux/amd64, linux/arm64, darwin/amd64, darwin/arm64, windows/amd64 서버 바이너리.
- 격리된 Mattermost Team Edition **10.11.10**에 번들 업로드·활성화 성공.
- 실제 관리자 화면에서 봇별 Thinking 설정 렌더링 확인. reasoning 허용 봇의 접힌 표시/펼치기 및 HTTP 오류 게시물의 reasoning 제거 확인.
- 실제 브라우저에서 질문 → 자동 RHS 열림 → 한글 Mermaid 렌더링 → body 팝업·확대·Escape·포커스 복귀 확인.
- 태그 reasoning을 포함하는 모의 스트리밍 응답을 사용해 최종 저장 게시물에 비공개 테스트 문자열이 없는 것을 확인. 실제 배포 중 처음 발견한 봇의 팀 미가입 오류도 공통 채널 가입 경로에서 수정하고 회귀 테스트 추가.
- 실제 사내 모델이나 사내 서버에는 접속하지 않았습니다. 공급자별 응답 형식은 모의 응답 및 단위 테스트로 검증했습니다.

`dist/com.mattermost.vllm-llm-0.3.0.tar.gz`와 옆의 `.sha256` 파일을 제공합니다. 기존 설정을 백업한 뒤 System Console의 Plugin Management에서 업로드하고 활성화하세요. 기존 봇은 reasoning 숨김·자동 RHS 활성화가 기본 적용되며 생성 파라미터는 기본적으로 추가하지 않습니다. 새 UI가 캐시된 경우 웹 클라이언트를 새로고침하세요. 문제가 있으면 보관한 v0.2.0 번들로 되돌릴 수 있습니다. 설치 파일은 [GitHub v0.3.0 릴리스](https://github.com/spsp4755/mattermost-llm/releases/tag/v0.3.0)에서도 내려받을 수 있습니다. 사내 배포는 관리자가 직접 수행합니다.
