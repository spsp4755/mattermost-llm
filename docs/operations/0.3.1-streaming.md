# v0.3.1 스트리밍 수정

## 원인과 변경

v0.3.0까지는 ‘가능하면 streaming 사용’을 켜도 `multimodal` 봇에서 스트리밍을 강제로 끄는 조건이 있었습니다. 이 조건은 첨부 없이 텍스트만 질문할 때도 적용됐습니다. v0.3.1에서는 봇 모드와 관계없이 활성화한 스트리밍 설정을 따릅니다. 스트리밍 요청이 실패하면 기존 일반 응답 전환 경로를 사용합니다. 여러 첨부를 먼저 처리하거나 후처리하는 작업의 중간 결과는 기존 작업 흐름을 따릅니다.

서버가 SSE 첫 답변을 flush한 뒤 클라이언트 콜백을 받기 전에는 완료 응답을 보내지 않는 HTTP 테스트를 추가했습니다. 텍스트/이미지 입력에서 완료 전 첫 답변 수신, 누적 답변, reasoning 숨김, `stream:true` 요청을 확인합니다. 기존 코드에서 실패하고 수정 후 통과하는 것을 확인했습니다.

## 배포 후 확인

1. v0.3.1 번들을 업로드하고 활성화합니다.
2. ‘가능하면 streaming 사용’을 켭니다. 갱신 간격 기본값은 800ms이며, 첫 테스트에서 200–500ms로 낮추면 조각별 표시를 확인하기 쉽습니다. 갱신을 자주 하면 Mattermost 게시물 갱신 부하가 늘어납니다.
3. 긴 텍스트 답변을 요청해 완료 전에 본문이 증가하는지 확인합니다. Reasoning 숨김 상태에서는 모델이 생각하는 동안 답변이 아직 안 보일 수 있습니다.
4. 여전히 한 번에 나오면 서버 로그의 `falling back to standard request`와 vLLM 앞단 프록시의 응답 버퍼링을 확인합니다. 플러그인 설정만으로 외부 프록시의 버퍼링을 해제하지는 않습니다.

## 팝업 및 웹 캐시 확인

v0.1.x의 버튼은 `복사 / 원문 보기 / 렌더 팝업`이고, v0.3.x의 버튼은 `코드 / 복사 / SVG / 확대`입니다. 관리 화면에 새 버전이 보여도 이미 열린 클라이언트는 이전 JavaScript를 유지할 수 있습니다.

- 브라우저에서 Ctrl+Shift+R 또는 시크릿 창으로 재접속합니다.
- 데스크톱 앱만 문제라면 새 브라우저 세션과 비교합니다.
- 새 세션에서도 이전 버튼이 보이면 정적 플러그인 JavaScript를 제공하는 프록시 캐시와 실제 설치 번들을 확인합니다.
- 새 버튼의 ‘확대’에서도 위치 문제가 재현되면 클라이언트 종류·버전과 해당 화면을 기준으로 별도 진단해야 합니다.

이번 패치에서 팝업 코드는 변경하지 않았습니다. 보고된 옛 버튼과 v0.3.x 코드가 일치하지 않아, 실제 사내 클라이언트의 로딩 상태 확인이 필요합니다. 실제 DeepSeek/vLLM 사내 엔드포인트 검증은 수행하지 않았으며 모의 SSE HTTP 서버로 검증했습니다.
